## Open risks - what a reviewer should attack hardest

1. **The number audit is the claim to test.** It compares 3,539 leaves; tolerance is allowed only on
   the database clock, the hour counts and stored timestamps. Break it deliberately: hard-code one
   number and confirm the build fails. Nobody has yet tried to make it pass when it should fail.
2. **The four Pages actions have never run in this repo** (`configure-pages@v5`,
   `upload-pages-artifact@v3`, `deploy-pages@v4`). A major-version mismatch would fail at deploy, not
   at build.
3. **`if: always()` publishes even when the pipeline failed.** That is deliberate - the health panel
   is the point - but it means the page can go live carrying yesterday's numbers. The top-of-page age
   notice is the only thing standing between that and a reader believing them.
4. **The registration block is a public claim about named businesses.** It states the coverage and
   that nothing was hand-checked, and `counterfeit` is banned from the page. A reviewer should read
   those four paragraphs as if they were the pharmacy's lawyer.
5. **The page is generated from views whose semantics have changed twice this week** (stock
   confidence, licence labels). If a view changes meaning, the page changes claim without changing a
   word.

## Unproven

- **Whether GitHub Pages accepts the artifact.** Pages is not enabled on the repo; that is the
  owner's decision, and until it is enabled this whole job is untested.
- **No axe run.** Accessibility was checked structurally and by measuring widths, not with an
  automated audit.
- **The page has not been read by a stranger.** It has been read by the person who commissioned it,
  which is not the same test.
- **Nothing was checked by hand against a pharmacy page or a NAFDAC record**, so the page's own
  statement that this has not happened is currently true and must stay true until someone does it.
